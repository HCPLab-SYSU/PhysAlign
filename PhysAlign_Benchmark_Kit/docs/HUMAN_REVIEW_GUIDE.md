# 人类开发审核：逐步操作与判例

本页指导原生草稿中原有的**开发审核页**。v1.1 新增的发布审核页、旧记录接入、独立二审和正式导出，请看 [RELEASE_WORKFLOW](RELEASE_WORKFLOW.md)；原开发页和本文所述操作没有被改写。

你审核的是“这个局部 QA 能否根据给定公开图文正确、唯一作答”，不是重解整道原题，也不是建立上千条角色/谓词注册表。

默认页面包含固定的 25 道开发母题及其全部已生成探针；实际不足时如实减少。它不是发布池的随机审计，也不是正式模型输入。

## 1. 打开和筛选

双击输出目录中的 `review.html`，不是工具源码目录的同名模板。无需服务器、API 或原 PhysGraph 标注 UI。原图与定位图通过相对路径加载，因此需要保留完整草稿文件夹；不要只把 HTML 发给审核员。

顶部填写真实审核人。状态先选“全部”，任务/子接口先选“全部”，再选一母题。按上一条/下一条检查同母题全部探针。任务下拉里旧 T01/T04/T05 不代表 native 中有这些题。

编号：R 是指定证据，E 是可选实体，V 是图片编号；回答用 E 而不是 V。H 是已知参考实体，本轮 native 两个任务族通常没有 H。同一个 E 可有多个几何部件/定位图。不同探针的 E 编号不能相互沿用。

## 2. 先盲判，保留首次判断

阅读公开提示和所有实际定位图，不先展开 key。回答的是“局部问题”，不是原题最后的求解问题。

| 接口 | 示例（E2 只是示意） |
|---|---|
| T02-single | `{"referent":"E2"}` |
| T03-image | `{"read":"m","owner":"E2"}` |
| T03-text | `{"owner":"E2"}` |

图像 read 是忠实转写，不计算表达式、不化简分数、不换单位。owner 保持原量的直接归属语义，不能因为另一个物体受到该力就将力自身的属性归属改给它。

无法唯一判断时填自然语言，例如“无法唯一判断：R1 同时指向两个位置，E1/E3 都合理”；当前界面只要求有独立判断记录，不会自动判分。不要为了看 key 先猜一个编号。

**导航不是保存。** 填写后只点下一条或换筛选会丢掉未提交内容。完成核查后点击“通过”或“退回”才进入本页内存记录。

## 3. 展开金标准与来源

点击“查看金标准与来源”，重点查看：

- `expected_binding_aliases`：编译所得正确 E。
- `read` 中 `expected`：图像读取的来源文本。
- `packet`：拟提供的局部转写，当前仍未获 Benchmark 批准。
- `source_records`：关联 collection、记录 ID、字段及源哈希。
- `native_diagnostics`：选择器、singleton_basis、表示类型、可复制性等；这些诊断不能替代你的判断。

语义/唯一性不确定时打开“完整 Pass4 来源”，核对 quantity.owner_id、refers_to 及相关证据；定位问题看 SourceAdapter 审计报告和原图。不能因为 key 与 JSON 互相一致就判事实正确。

## 4. 六项检查分别怎么判

1. **来源支持语义**：公开问题与源事实对应，没有补物理假设、偷用 Pass5 或把绑定变成新推导。
2. **目标闭合**：公开输入确实支持单对象/单归属；不是删掉另一条边之后才“唯一”。范围/阶段/面板有歧义就退回。
3. **候选可区分**：每个 E 有明确指代，不同 E 没有实际指向同一对象；不能只靠私有名称才知道对应关系。
4. **定位精确**：R 的文字完整，E 不是另一对象；没有关键区域缺失、严重遮挡或多候选混框。稍大但不影响区分可以记小瑕疵。
5. **packet 不泄漏绑定结论**：局部转写忠实于独立源图文字，没有额外告诉模型正确 E、owner 或分析答案。空 packet 无此内容可核对时，确认确实为空并注明“不适用：无 packet”后勾选；不是要求你补内容。
6. **图像范围正确**：读取/packet 区域属于题图，不是图像型原选项、解答或无关背景。文本分支没有图像 read 时，注明“不适用：无图像 read”，但 E 的显示图仍需检查。

如果某检查项的含义确实无法确认，不为点通过而机械全勾。

## 5. 通过、退回以及不应退回的情况

全部关键条件成立后勾选六项，点“确认本条通过”。有明确错误或未决问题，写原因后点“退回本条”；退回会记录意见，不删原题或原标注。

建议备注格式：

```text
[定位错误] R1 漏掉数值，只覆盖了 kg；请核查 v003 的完整文字区域。
[归属疑点] q004.owner_id 与公开题干的归属不符；我判断为 E1，key 为 E3。
[唯一性不足] 两个阶段都标 A，公开 R 没区分阶段，E2/E4 均合理。
[候选重复] E1 与 E3 指向同一物体的相同位置，无法区分。
[小瑕疵] 框稍大但对象明确，不影响作答；建议统一显示留白。
```

不要把首次盲答改成 key 来制造一致率。若发现是自己漏看信息，可以通过，备注“首次漏看某条件，复核后来源/公开输入支持 key”，保留原始盲答。若公开输入本来不足以作答，不能因看了私有来源才懂就通过。

题目简单、最近区域就能猜对、原题文字已有相同读数、owner 是力或场，都不是自动退回理由。可复制性、表示类型和几何策略会分层报告；不要按模型/人的难易筛选到只剩错题。

label_only / mixed 是表示诊断，不是一键判坏：若标签不足以唯一定位实体，退回并说明；若公开输入确实可辨认，按具体事实审核，不改变诊断来提高数据量。

## 6. 保存、继续、检查是否漏审

页面只在当前浏览器页面的内存中保存记录，没有后台自动写回。每完成一道母题都建议点“导出审核 JSON”；选择草稿目录之外的位置，避免破坏 FILE_MANIFEST。

刷新/关闭前务必导出。下次先填写审核人，再选择“导入此前导出的审核 JSON”。文件绑定当前 catalog_root 和每条 review_target_root；不能导入另一版本的审核文件。浏览器有可能把重复下载命名为 `(1)`、`(2)`，请确认最终提交的是最新的一份。

审核完成后把母题、任务、子接口都切到“全部”，状态切到“未审核”，检查没有遗漏。已审核计数包含通过与退回，不只通过；可再用：

```bash
python -B -X utf8 tools/check_review.py --draft "../physalign_outputs/team_a_native_v1" --decisions "../physalign_reviews/team_a_dev_v1.json"
```

检查脚本会列出 pending、完成母题、退回说明是否为空；它不检查你的物理判断是否正确，也不产生批准发布。完整源/图/Schema 复验另跑 native-validate。

不要把审核意见写到原 Pass JSON，不要在生成草稿中直接改 E/read/owner/框坐标。开发问题应交给负责人分析规则影响，必要时在可信来源流程中修改并重新审核源，再生成新草稿版本。

## 7. 团队交付与后续

提交同版本 draft、最新审核 JSON、主要疑点说明和工具包版本。原始数据/审核文件单独走授权团队渠道，不混入工具分享包。开发盲判只是流程记录，不是防作弊系统；同母题多个探针不当作独立人类测量样本。

当前这个旧开发页面没有批次批准/冻结按钮，旧 freeze 仍被 native 拦截。开发闭环完成后，按 RELEASE_WORKFLOW 使用新发布入口接入导出的记录，完成相应准入；不要把本页面的通过状态本身宣传成已完成正式 Benchmark 审计。
